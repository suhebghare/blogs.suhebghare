Choosing the Right AWS Storage

AWS has 15+ storage options. Most teams only need 4: S3, EBS, EFS, and occasionally FSx. The trick is knowing which one fits your access pattern — and the cost difference between getting it right and wrong can be 5-10x.

Intelligent-Tiering: The Default Choice

For most workloads, Intelligent-Tiering is the right answer. It automatically moves objects between tiers based on access patterns. No retrieval fees, no minimum duration penalty. The only cost is a small monitoring fee ($0.0025 per 1,000 objects/month).

resource "aws_s3_bucket_intelligent_tiering_configuration" "data_lake" {
  bucket = aws_s3_bucket.data_lake.id
  name   = "full-bucket-tiering"

  tiering {
    access_tier = "ARCHIVE_ACCESS"
    days        = 90
  }
  tiering {
    access_tier = "DEEP_ARCHIVE_ACCESS"
    days        = 180
  }
}

Lifecycle Policies: $12K → $7K/Month

We had 60TB of application logs in S3 Standard. Analysis showed: last 7 days accessed frequently, 7-30 days accessed occasionally, 30-90 days rarely, 90+ days never (but needed for compliance).

resource "aws_s3_bucket_lifecycle_configuration" "logs" {
  bucket = aws_s3_bucket.app_logs.id

  rule {
    id     = "log-lifecycle"
    status = "Enabled"

    transition {
      days          = 30
      storage_class = "STANDARD_IA"
    }
    transition {
      days          = 90
      storage_class = "GLACIER_IR"    # Glacier Instant Retrieval
    }
    transition {
      days          = 365
      storage_class = "DEEP_ARCHIVE"
    }
    expiration {
      days = 2555  # 7 years for compliance
    }
  }
}

S3 Performance Tips

  • Multipart upload: Required for files >5GB, recommended for >100MB. Parallel uploads dramatically improve throughput.
  • S3 Transfer Acceleration: Uses CloudFront edge locations for faster uploads from distant regions. 50-500% faster for cross-region transfers. Costs $0.04/GB.
  • Prefix partitioning: S3 supports 5,500 GET/s and 3,500 PUT/s per prefix. Spread objects across prefixes for high-throughput workloads.

gp3 vs gp2: Migrate Everything

gp3 is 20% cheaper than gp2 AND gives you 3,000 IOPS baseline (gp2 only gives 3,000 if your volume is 1TB+). Plus gp3 lets you independently tune IOPS and throughput. There is zero reason to use gp2 for new volumes. Migrate existing gp2 volumes — it's a live operation with no downtime.

# Migrate gp2 to gp3 (no downtime)
aws ec2 modify-volume \
  --volume-id vol-0123456789abcdef0 \
  --volume-type gp3 \
  --iops 3000 \
  --throughput 125

# Monitor migration progress
aws ec2 describe-volumes-modifications \
  --volume-ids vol-0123456789abcdef0

Snapshot Strategy

# Automated snapshots with lifecycle policy
resource "aws_dlm_lifecycle_policy" "ebs_snapshots" {
  description        = "EBS snapshot lifecycle"
  execution_role_arn = aws_iam_role.dlm.arn
  state              = "ENABLED"

  policy_details {
    resource_types = ["VOLUME"]
    target_tags    = { Backup = "true" }

    schedule {
      name = "daily-snapshots"
      create_rule { interval = 24; interval_unit = "HOURS"; times = ["03:00"] }
      retain_rule { count = 14 }  # Keep 14 daily snapshots
      copy_tags = true
    }
  }
}

Real Incident: gp2 Burst Credit Exhaustion

The 3 AM Page

Our RDS instance (500GB gp2 volume) started showing 200ms query latency spikes every afternoon. The volume had 1,500 baseline IOPS (3 IOPS/GB × 500GB) but the database needed 2,500 IOPS during peak hours. It was burning through burst credits during the day and running out by 3 PM. Migrated to gp3 with 3,000 baseline IOPS — latency dropped to 2ms and the cost went DOWN by 20%.

EFS: Shared Filesystem for Containers

EFS is NFS-as-a-service. It's the only option when multiple EC2 instances or containers need to read/write the same files simultaneously.

EFS Cost Warning

EFS is 3.75x more expensive than EBS per GB. Only use it when you genuinely need shared access. I've seen teams use EFS for single-instance workloads because "it auto-scales" — they were paying $0.30/GB instead of $0.08/GB for no benefit. Use EFS for: shared config, shared uploads directory, CMS media files accessed by multiple containers.

EFS Throughput Modes

  • Bursting: Throughput scales with storage size. 50 KB/s per GB baseline. A 100GB filesystem gets 5 MB/s baseline with burst to 100 MB/s. Fine for most workloads.
  • Elastic (recommended): Automatically scales throughput up to 10 GB/s. Pay per GB transferred. Best for unpredictable workloads.
  • Provisioned: Fixed throughput regardless of size. Use when you need consistent high throughput on a small filesystem.

FSx: Specialized Filesystems

FSx for Windows (SMB)

  • Windows file shares with Active Directory
  • SMB protocol, DFS namespaces
  • Migrating on-prem Windows file servers
  • From $0.013/GB/month (single-AZ HDD)

FSx for Lustre (HPC)

  • Sub-millisecond latency, hundreds of GB/s throughput
  • Integrates with S3 (lazy-load data)
  • ML training, genomics, financial modeling
  • From $0.14/GB/month

Key Takeaways

  • S3 Intelligent-Tiering should be your default for object storage
  • Migrate all gp2 volumes to gp3 — 20% cheaper, better baseline IOPS
  • EFS only when you need multi-instance shared access — it's 3.75x the cost of EBS
  • Lifecycle policies on S3 can save 40-60% on storage costs
  • Monitor EBS burst credits (gp2) or switch to gp3 to avoid latency spikes
  • Use S3 Transfer Acceleration for cross-region uploads
  • Snapshot lifecycle policies prevent snapshot sprawl (we found $1,800/mo in old snapshots)
