Order Matters

Don't buy Savings Plans first. I've seen teams commit to Reserved Instances before right-sizing — they locked in the wrong instance types for 1 year. Always optimize first, commit last.

Phase 1: Visibility — You Can't Optimize What You Can't See

We started by tagging every resource with team, environment, service, and cost-center. Then built per-team dashboards in AWS Cost Explorer.

# Enforce tagging with AWS Config rule
resource "aws_config_config_rule" "required_tags" {
  name = "required-tags"
  source {
    owner             = "AWS"
    source_identifier = "REQUIRED_TAGS"
  }
  input_parameters = jsonencode({
    tag1Key   = "team"
    tag2Key   = "environment"
    tag3Key   = "service"
    tag4Key   = "cost-center"
  })
}

# SCP to prevent untagged resource creation
resource "aws_organizations_policy" "require_tags" {
  name    = "require-tags"
  content = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Sid       = "DenyUntaggedEC2"
      Effect    = "Deny"
      Action    = ["ec2:RunInstances"]
      Resource  = ["arn:aws:ec2:*:*:instance/*"]
      Condition = {
        "StringEquals" = {
          "aws:RequestTag/team" = ""
        }
      }
    }]
  })
}

Within 2 weeks, we had visibility into which team was spending what. The data team was 42% of the bill — mostly oversized EMR clusters running 24/7 for jobs that ran 3 hours/day.

Right-sizing EC2 instances saved us $28K/month alone. Most instances were using less than 20% of their allocated CPU.

Switching to Graviton (ARM) instances gave us 20% better price/performance. Same workload, lower cost. We moved all stateless services to Graviton in 2 weeks. The only blocker was one service with a native x86 dependency — we kept that on Intel.

Phase 3: Waste Elimination — The Low-Hanging Fruit

We wrote a script that runs weekly to find waste. Here's what we found in the first scan:

Unattached EBS volumes (47 volumes)
$1,800/mo
Old EBS snapshots (>90 days, 2.3TB)
$2,100/mo
Idle NAT Gateways (3 unused VPCs)
$450/mo
Unused Elastic IPs (18 addresses)
# Find unattached EBS volumes
aws ec2 describe-volumes \
  --filters "Name=status,Values=available" \
  --query 'Volumes[*].{ID:VolumeId,Size:Size,Created:CreateTime,Type:VolumeType}' \
  --output table

# Find unused Elastic IPs
aws ec2 describe-addresses \
  --query 'Addresses[?AssociationId==null].{IP:PublicIp,AllocID:AllocationId}' \
  --output table

# Find old snapshots (>90 days)
aws ec2 describe-snapshots --owner-ids self \
  --query "Snapshots[?StartTime<='$(date -d '-90 days' +%Y-%m-%d)'].{ID:SnapshotId,Size:VolumeSize,Date:StartTime}" \
  --output table

Phase 4: Architecture Optimization

S3 Intelligent-Tiering: $8K/Month Saved

We had 45TB in S3 Standard. Analysis showed 70% of objects hadn't been accessed in 30+ days. Instead of manually managing lifecycle policies, we enabled Intelligent-Tiering.

resource "aws_s3_bucket_intelligent_tiering_configuration" "main" {
  bucket = aws_s3_bucket.data.id
  name   = "full-bucket-tiering"

  tiering {
    access_tier = "DEEP_ARCHIVE_ACCESS"
    days        = 180
  }
  tiering {
    access_tier = "ARCHIVE_ACCESS"
    days        = 90
  }
}
S3 Standard: $0.023/GB → Intelligent-Tiering Archive: $0.004/GB (83% cheaper)

CloudFront Caching: Reduced Data Transfer by 60%

Our API responses were cacheable for 60 seconds but we weren't using CloudFront. Adding a CDN with cache-control headers cut our data transfer costs from $12K to $4.8K/month.

Lambda for Bursty Workloads

We had 4 EC2 instances running 24/7 for a webhook processor that was busy 2 hours/day. Moved to Lambda — cost went from $1,200/month to $85/month.

Phase 5: Commitment Discounts

After 3 months of optimized spending, we had stable baseline usage to commit against.

StrategyDiscountFlexibilityBest For
Compute Savings PlansUp to 66%Any instance family, region, OSMost workloads — start here
EC2 Instance Savings PlansUp to 72%Specific instance family + regionStable, predictable workloads
Reserved InstancesUp to 72%Specific instance type + AZDatabases, fixed infrastructure
Coverage Target: 70-80%

Don't try to cover 100% of your spend with commitments. Aim for 70-80% coverage of your steady-state baseline. The remaining 20-30% should be On-Demand or Spot for flexibility. We committed $65K/month in Compute Savings Plans (1-year, no upfront) — saving an additional $22K/month.

The Monthly Cost Review Process

Week 1: Automated Waste Scan

Script runs, generates report of unattached volumes, idle resources, underutilized instances. Auto-tags resources for review.

Week 2: Team Cost Review

Each team reviews their spend vs budget. Top 3 cost drivers identified. Action items assigned.

Week 3: Architecture Review

Review any service spending >$5K/month. Can it be optimized? Different instance type? Different architecture?

Week 4: Commitment Review

Review Savings Plan utilization and coverage. Adjust commitments if usage patterns changed.

Key Takeaways

  • Tag everything — you can't optimize what you can't measure
  • Right-size before committing — don't lock in the wrong instance types
  • Graviton instances are a free 20% discount for most workloads
  • Run waste detection weekly, not quarterly
  • S3 Intelligent-Tiering is almost always the right choice
  • Aim for 70-80% Savings Plan coverage, not 100%
  • Make cost a team metric, not just a finance metric
